# Instagram Reels：Meta 原生排程規格

2026-11-03 使用者核准的有效規格。取代[原雲端／API 版本](history/instagram-reels-publishing-before-native.md)；歷史故事編號僅供追溯，衝突以本文件及新版票據為準。

## 完整流程

成片交付到設定的待發佈資料夾 → 每兩個日曆日 Asia/Taipei 08:00，Codex 掃描並核對原生排程／已發佈結果 → 新候選在同一審核對話填文案、預覽並核准確切版本 → 準備完成即經 Meta Business Suite 上傳，保存隔日 20:00 的原生排程 → Meta 到時發佈 → 核對正式結果 → 本機原片歸檔。

掃描與核對依賴 Mac／Codex 可用；錯過只補掃一次，保留日曆節奏。已保存於 Meta 的排程由 Meta 執行，不以本機、Codex 或自建雲端定時器到點呼叫 API。20:00 是目標時間，不保證平台零延遲。

## 不變條件

- 本機核准、已上傳、Meta 已排程、結果不明、已發佈、本機已歸檔是不同狀態。Meta 原生排程成功必須在重新載入後核對指定帳號、完整文案、時間／時區、公開可見性與不跨貼 Facebook。
- 核准綁定原片指紋、上傳檔指紋、完整文案與發佈時刻。轉碼檔與原片保持明確對應；修改影像內容需另行核准。排程保存即保留原片，不移入已發佈。
- 每次外部建立／修改／取消前先持久保存唯一操作意圖；中斷或回應不明視為待核對，僅讀取平台恢復。不因再次掃描、未出現在 IG app、空清單或逾時而另建排程或送 API 補發。
- 修改／取消作用在已識別的 Meta 排程；重新核准確切變更後才寫入，重新載入核對。未確認前仍以舊平台安排可能有效對待，不宣稱撤銷成功。已公開項目不自動刪除。其他影片的日期保持不變。
- 到原發佈日晚間 20:30，若尚無正式成功證據，標記需核對／介入；這是異常檢查門檻，已取消「20:30 前自動補發」。兩天掃描只在下一次可用時發現／提醒，不承諾當晚即時通知。
- Meta 已發佈記錄（或可核對 IG 正式貼文）為成功來源。必須對應帳號及既有排程／上傳內容，保存證據及獨立正式媒體 ID／連結；排程 ID 永不當成 IG 媒體 ID。查不到不等於失敗或已取消。
- 成功後才歸檔原片；指紋不符、缺檔、同名衝突只使歸檔待整理，不撤回成功、不重新發佈。歸檔可重跑，不能覆寫成片或刪除已被替換的來源；受控原片恢復副本保留，不自動刪除。
- Codex 是唯一主要提醒來源；沿用同一資料庫、審核對話及通知回執。無新變化保持安靜，回報產生不等於送達確認。停止掃描／停用 plugin 不會取消 Meta 既有排程。
- 撤銷自建雲端媒體儲存、排程部署、API 自動補發與七天雲端清理要求；不承諾刪除 Meta 內部副本。本機上傳副本只可在成功歸檔或已確認取消後，明確清理本工具管理的私有副本，原片與證據保留。

## 驗證與交付界線

公開 Workflow／CLI 驗證核准、持久意圖、證據收錄、競爭防護、通知去重與歸檔；使用真實 SQLite、檔案及可控制時間。外部 UI 由可用的 computer use 操作，CLI 收錄操作員實際觀察的結構化回執，本機回執本身不能獨立證明 Meta 真實狀態。

真實驗收分開保存：指定帳號、上傳、保存及重新載入核對、修改／取消、到點正式公開、離線後同步與歸檔、Codex 到期實際提醒。未觀察到的仍未完成。今晚已核准的排程不作修改／取消試驗。

API 讀取成功與測試工具保留，但原 API media_publish 真實發文驗收另列暫緩；原生 UI 發佈不能替代。新 plugin 安裝不讀憑證、不發佈舊影片；完整發佈驗收仍依賴上述真實結果。
