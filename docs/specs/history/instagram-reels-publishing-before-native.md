## Problem Statement

使用者目前透過個人剪輯技能產生成片，但仍需手動查看待發佈資料夾、整理文案、安排 Instagram 發佈及整理成片。使用者希望工具定時發現新影片，由本人決定文案並審核，再依固定節奏自動發佈至 @_eric_han，即使 Mac 關機也能執行。現有匯出技能只交付成片，沒有社群 API、雲端排程或狀態同步能力。

## Solution

將本機成片發現、對話審核、官方 Instagram API 與雲端排程整合為可納入個人剪輯 plugin 的工具。

Mac 可用時每兩天掃描一次待發佈資料夾；新影片經內容比對後形成候選排程，寄 Email 提醒使用者回到對話填寫文案、確認順序與時間。只有核准且已完成雲端傳送的項目才能啟用。雲端按使用者指定的首發日期，每隔一個日曆日於台北時間 20:00 執行正式發佈；成功結果同步回本機後，將影片移入已發佈。

待發佈、候選排程、已排程與已發佈各有不同意義；候選排程不具有自動發佈授權，排程或上傳成功也不等於已發佈。

## User Stories

1. As an 帳號持有人, I want 使用官方方式授權我的指定 Instagram 帳號, so that 工具能代表正確帳號發佈。
2. As an 使用者, I want 每兩天自動掃描待發佈資料夾, so that 不必每批手動要求找影片。
3. As an 使用者, I want 關機或休眠錯過的掃描在 Mac 恢復可用後補掃, so that 新成片不會永久遺漏。
4. As an 使用者, I want 工具只接收已完成且可讀取的成片, so that 複製中、無法讀取或不適用的檔案不會形成可發佈任務。
5. As an 使用者, I want 根據影片內容辨識重複項目, so that 改名或重複掃描不會重複排程。
6. As an 使用者, I want 初次啟用時比對既有已發佈影片, so that 既有成片不會無意間再次排程。
7. As an 使用者, I want 既有本機歸檔與平台成功紀錄被明確區別, so that 不把資料夾名稱當成 IG 發佈證據。
8. As an 使用者, I want 發現新影片後收到一次 Email 提醒, so that 知道有候選排程等我審核。
9. As an 使用者, I want 重複掃描同一支待審影片不重複寄提醒, so that 不被固定通知打擾。
10. As an 使用者, I want 在對話中指定每支影片的發佈文案, so that 貼文文字由我決定。
11. As an 使用者, I want 查看並調整候選排程的影片順序, so that 不受檔案建立時間影響。
12. As an 使用者, I want 排程清單清楚列出影片、文案、順序、日期與時區, so that 能一次檢查整批內容。
13. As an 使用者, I want 未填完文案或未核准的影片不會發佈, so that 發現影片不等於授權發佈。
14. As an 使用者, I want 一次確認整批安排, so that 核准後不用在每次發佈時再次操作。
15. As an 使用者, I want 首次啟用時指定首發日期, so that 固定發片節奏從我選定的日期開始。
16. As an 使用者, I want 每隔一天於台北時間 20:00 發佈一支, so that 發佈節奏固定且可預期。
17. As an 使用者, I want 新批次接在最後一筆有效排程後的可用固定時段, so that 不打亂已安排的影片。
18. As an 使用者, I want 審核太晚時重新查看下一個有效候選時間, so that 不會突然立即發佈。
19. As an 使用者, I want 核准後修改文案、影片內容或順序時重新確認受影響的安排, so that 實際發佈仍符合我的授權。
20. As an 使用者, I want Mac 關機後已啟用的雲端排程仍可執行, so that 發片不依賴我的電腦在線。
21. As an 使用者, I want 傳送失敗或未啟用的項目有明確狀態, so that 不誤以為影片已準備好自動發佈。
22. As an 使用者, I want 只有平台正式發佈成功才顯示已發佈, so that 排程、上傳與公開結果不混淆。
23. As an 使用者, I want 成功後保存平台媒體識別碼及可取得的貼文連結, so that 能核對結果。
24. As an 使用者, I want Mac 下次連線時同步雲端結果並整理資料夾, so that 離線期間的成功發佈仍能歸檔。
25. As an 使用者, I want 本機移動失敗不導致重複發佈或誤報歸檔成功, so that 能修復檔案問題而不影響平台結果。
26. As an 使用者, I want 發佈失敗在可確認不重複的前提下補發至當晚 20:30, so that 暫時性故障有恢復機會。
27. As an 使用者, I want 平台回應不明時先停止重試並核對, so that 不因網路中斷重複發片。
28. As an 使用者, I want 需要處理的失敗、授權失效或不明結果透過 Email 通知, so that Mac 關機時也知道需要介入。
29. As an 使用者, I want 單支失敗不自動挪動後續日期, so that 其他已核准安排維持不變。
30. As an 使用者, I want 沒有已核准影片的時段直接跳過並保留原節奏, so that 不發生臨時插播。
31. As an 使用者, I want 取消尚未開始正式發佈的排程並查看結果, so that 能確定工具是否成功阻止發片。
32. As an 使用者, I want 取消留下的空位不改動其他影片日期, so that 整批安排穩定。
33. As an 使用者, I want 本機改名、移動或刪檔不會暗中取消雲端排程, so that 日常整理不改變已核准安排。
34. As an 使用者, I want 明確指定重發才能讓已辨識的重複影片再次入列, so that 重發是刻意選擇。
35. As an 使用者, I want 發佈成功七天後清理雲端影片而保留本機成片及發佈紀錄, so that 不長期存放不必要的雲端副本。
36. As an 使用者, I want 未成功或待核對的影片不被成功清理規則刪除, so that 仍可調查及恢復。
37. As an 使用者, I want 優先使用免費方案做小量驗證並在付費前確認費用, so that 成本在我的控制內。
38. As an 使用者, I want 功能與既有剪輯技能一起管理且可整合成個人 plugin, so that 保持單一剪輯到發佈的工作流程。

## Implementation Decisions

- 單一使用者、單一指定 IG 帳號，使用官方授權與發佈介面；實際權限、帳號識別及 token 有效性須驗證，不依公開帳號頁面推定授權成功。
- 功能分為本機成片發現與同步、發佈工作流程、外部平台與通知整合。既有匯出技能維持交付成片責任，新增工具承接發佈，不將定時發片只寫成技能指示。
- 對話中的工具操作與背景工作共用同一套發佈工作流程規則；具體工具協定、執行語言與服務供應商在開發規劃階段選擇。
- 本機掃描與雲端發佈是獨立任務。掃描每兩天一次，首次日期與時間在啟用時配置；Mac 不可用期間無法發現僅存於本機的新影片，恢復後補掃且不重複入列。
- 對齊實際成片來源與既有安裝版技能使用的資料夾，修正 repo 版輸出位置不一致的問題。只處理指定成片來源，不以整個桌面作為輸入。
- 用影片內容辨識重複項目，並保存待審、已核准與發佈歷史；改名不是新影片，改變內容也不能沿用舊內容的核准。
- 候選排程必須保存待核准內容與有效性。審核、傳送、啟用需有可恢復進度；不因資料夾移動成功就判定已啟用，也不因移動失敗再發一次。
- 發佈採 Asia/Taipei，使用使用者指定的首發日期作為固定隔日節奏起點，每個時段一支。空缺或取消不改變節奏；新批次接續既有有效安排，過期候選需重新確認。
- 核准綁定具體影片內容、文案、順序與時間。啟用前核對該版本；上傳不完整、文案缺漏或尚未核准皆不得正式發佈。核准後的相關變更必須重新確認受影響項目。
- 雲端保存已啟用排程及發佈結果，本機歸檔跟隨可核對的結果。本機刪改檔不等於取消雲端任務，取消須由明確操作及確認結果表示。
- 排程到點執行平台正式發佈流程，須先滿足媒體處理就緒條件。20:00 是目標發佈時間，不保證第三方平台零延遲公開；不得將晚到或失敗宣稱準時成功。
- 補發限當晚 20:30 前，先判斷是否可安全重試。正式發佈結果不明時暫停補發並核對，不能直接當成未發佈；超時或需介入的失敗通知使用者，不改動後續日期。
- 取消與正式發佈競爭時須回報真實結果；已進入正式發佈不保證可取消，也不自動刪除已公開貼文。
- Email 用於新候選審核提醒及需介入事件，重複掃描不重複提醒同一候選。成功結果留在排程清單，通知寄送失敗不可改寫平台發佈結果。
- 成功後七天清理雲端影片副本，保留本機成片及發佈紀錄；未成功及待核對項目不使用成功清理規則。取消或停用時的媒體清理與憑證撤銷操作於開發規劃補齊。
- 憑證保存在適合執行環境的秘密儲存中，不提交至 GitHub、不顯示於一般日誌或聊天；媒體存放需符合所選官方上傳方式的可讀取條件，不能把本機路徑當成遠端影片 URL。
- 優先免費方案驗證，選型時列出容量、持續執行、儲存與寄信限制。付費服務部署或升級前須取得具體費用方案的確認。

## Testing Decisions

使用者已確認以下驗證邊界。主測試入口設在工具與背景任務共同使用的發佈工作流程公開操作；從發現影片、候選審核、啟用、到點處理到同步結果，驗證外部可見行為，避免分別測試每個內部函式。

- 透過上述共同入口，以可控制的時間及測試用 IG、媒體儲存、Email 與本機檔案環境，驗證候選清單、核准版本、發佈請求、通知、檔案位置及持久結果；不斷言內部函式呼叫順序或私有資料結構。
- 核心驗證涵蓋：每兩天掃描與補掃、防重複及明確重發、文案未完成或未核准不發佈、批次順序、固定時區與首發節奏、候選過期、核准後變更、空位與取消保留節奏。
- 恢復驗證涵蓋：傳送中斷、執行服務重啟、相同工作被再次觸發、Mac 離線與恢復、平台處理未完成、明確失敗、安全重試至 20:30、平台已成功但回應遺失、不明結果、取消與發佈競爭、本機歸檔失敗。上述情況不能以盲目重試造成重複發佈。
- 資料與通知驗證涵蓋：新候選只提醒一次、授權失效與失敗通知、寄信失敗不改寫發佈狀態、成功後七天清理只影響雲端影片、不刪本機與待核對影片、不在輸出洩漏憑證。
- 另需少量真實整合驗證，確認 Meta 授權、影片傳輸、正式發佈結果及 Email 寄送；測試替身不能證明真實 API 可用。任何真實公開發佈須先取得指定影片、文案及時間的授權，不能把本規格或測試批准視為發文批准。
- 部署驗證應涵蓋關閉本機掃描端時雲端仍執行已核准任務，以及本機恢復後正確歸檔。不能只用模擬時間測試推定部署後排程可靠。
- 現有 repo 僅有技能與參考資源，沒有可沿用的執行服務或自動化測試框架。既有字幕與匯出技能的格式／畫面檢查不構成新發佈服務的測試先例；以新增的共同工作流程入口作為主要驗證邊界。

## Out of Scope

- 多使用者服務、多帳號管理、其他社群平台與廣告投放。
- 重新剪輯、字幕生成、IG 原生音樂庫選曲、限時動態或其他非 Reels 發佈格式。
- 自動生成並直接核准文案、未經審核自動發佈、根據資料夾存在推定授權。
- 新建文案編輯網站、完整社群分析後台或公開 plugin 上架。
- Mac 關機時讀取尚未上傳的本機影片，以及未經確認的付費部署。
- 自動刪除已公開貼文，或把既有已發佈資料夾回填為已驗證的 IG 歷史。
