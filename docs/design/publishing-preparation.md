## 原型已涵蓋及限制

| 任務 | 可重現的準備 | 真實驗收仍缺 |
| --- | --- | --- |
| #5 | 核准版本匯出、傳送／啟用分開、內容核對、持久工作與重複觸發 | #2、官方上傳、真正媒體準備與輪詢、雲端部署、關機驗證、上傳分段恢復 |
| #6 | 明確取消、真實狀態回傳、不挪其他日期；修改停止舊版本、新核准另啟用 | 對話工具與遠端版本權威連接、跨程序雲端競爭與通訊結果不明 |
| #8 | 明確未發佈才補發、20:30 排除邊界、回應遺失／程序中斷後核對、事件通知去重 | 官方平台對錯誤的可靠分類、真實 Email 與可查核對識別；原型 IncidentSink 不連 SMTP |
| #9 | 成功後才歸檔、拒絕覆寫、歸檔失敗不重發、可重跑 | 雲端結果同步協定、已啟用移入已排程、改名搜尋、跨磁碟歸檔恢復與實機離線驗證 |
| #10 | 核實成功／確認時間七天後清理、有效共享副本保留、本機與 receipt 保留 | 真實物件儲存的命名空間與權限限制、刪除驗證、取消暫存清理工具 |

原型不接受網路配置或 token；它不是可直接升級為 production 的雲端服務。ApprovedRelease 是審核快照，不是可授權第三方伺服器執行發佈的憑證。正式遠端必須驗證呼叫者、最新核准版本及內容，不能只信任呼叫端送來的 revision。舊快照在本機修改後也不能自行沿用。

原型取消使用單一程序鎖序列化操作；在正式發佈已開始時回傳 publishing／unknown／succeeded，而不宣稱取消成功。真正雲端需以持久資料庫條件更新與 attempt fence 取得唯一執行權；程序在 publishing 中斷後只核對，不重新取得發佈權。沒有平台成功證據時，查不到貼文也不代表確定未發佈。

原型的 succeeded_at 在回應遺失後使用核對成功時間作保守保留起點，不會提早清理；正式整合需保存可核實的實際平台成功時間與核對時間。NotPublished 僅代表測試替身提供的「確定未正式發佈」證據，不能把所有 HTTP error／timeout 都轉成它。

## 建議部署設計，尚未選定服務

建議先驗證 Cloudflare Workers + D1 + R2，小量免費額度與尚待確認的帳務條件見 [服務核實](../research/cloud-publishing-feasibility.md)。這是建議，不是開通或費用授權。

1. 本機送核准快照到受驗證的控制入口，建立固定 idempotency key。影片直接／分段上傳物件儲存，伺服端核對內容與完整性，不能整支經 Worker 記憶體轉送。
2. 雲端保存 immutable release、媒體版本及任務狀態。只有最新有效核准、完整上傳、日期未過期才可條件啟用。重送啟用需查同一工作結果；逾時不能建立新工作。
3. 每分鐘觸發只處理到期任務；隔日節奏由 Asia/Taipei 首發日推算並保存具體日期，不能用每月日欄位 */2 代替。20:00 對應 UTC 12:00，準備、輪詢、發佈分次保存進度。無任務時跳過。
4. 正式發佈前先持久記錄唯一 attempt 與 publishing。明確未發佈才能在 20:30 前補發；結果不明停止新嘗試並建立介入通知。取消、修改及停用都需持久回應，不能把送出請求視為成功。
5. 本機同步只相信受驗證的雲端結果，保留平台 receipt 與獨立歸檔狀態。七天清理只刪指定媒體命名空間，刪除前重新查所有有效引用，不能用 bucket-wide lifecycle 規則刪除未成功影片。

## #11 plugin 準備與停用順序

尚未封裝或安裝 plugin，避免把缺少部署的操作包裝為可用功能。既有字幕與匯出技能不變，不新增文案網站。

正式封裝時：既有技能 + 同一工作流程的對話工具入口；工具需包含候選、填文案、預覽、核准、傳送狀態、啟用、修改、取消、結果同步及介入狀態。安裝本身不設定 cron、不掃描、不寄信、不啟用舊影片；先回傳缺項，完成非秘密配置及私有憑證後再逐項授權啟用。

停用分開處理：停止本機掃描 → 明確暫停／取消雲端未開始工作並核對結果 → 解決 publishing／unknown → 確認保留紀錄及媒體後處理取消暫存 → 透過供應商官方流程撤銷指定應用程式權限及憑證。停止掃描不取消雲端。未核對結果不清理媒體；撤銷前需確認不再需要以原憑證核對，必要時轉人工處理。此處只是操作設計，沒有執行撤銷。
