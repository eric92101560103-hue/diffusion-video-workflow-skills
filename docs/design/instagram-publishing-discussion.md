# Instagram 發佈流程討論

狀態：流程決策已逐項確認，待使用者確認整體理解；尚未核准實作。更新：2026-10-29。

## 已確認

- 目標為使用者的 @_eric_han 帳號，以官方 API 自行串接，與剪輯 skills 一起發展為個人 plugin。
- 待發佈 → 已排程 → 已發佈三階段；只有取得正式發佈成功結果後才移入已發佈。失敗保留在已排程並標示原因。
- 使用雲端排程，影片與文案須事先完成傳送；Mac 關機或休眠時仍可發佈。雲端服務與費用尚未選定。
- 使用者先確認排程清單中的影片、文案、時間與順序，核准後到點直接發佈，不逐支再次詢問。
- 以 Asia/Taipei 為準，每隔一個日曆日 20:00 發佈一支，首發日期由使用者指定。
- Agent 可提出候選順序，最終由使用者調整確認，不依檔案建立時間直接決定。
- 文案先在對話中指定，由 Agent 整理成排程清單供使用者修改並整批確認；第一版不另建文案編輯網站。
- 新批次自動接在最後一筆有效排程之後，沿用隔日 20:00 節奏。首次啟用時指定首發日期；核准後修改文案或順序，受影響的項目需要重新確認。
- 發佈失敗允許當晚最多延後 30 分鐘補發；只在確認不會重複發佈時重試。無法確定平台是否已收到時停止補發並核對結果。超過補發期限仍失敗則暫停該支並通知使用者，後續影片維持原日期。
- Mac 關機時由雲端更新發佈結果，待本機同步程式開機連網後，再把成功影片移入已發佈。
- 沒有已確認影片可發時跳過當次，維持原本日期節奏，不自動插入隔日補發。
- 取消尚未開始正式發佈的任務時，保留其他影片的原日期，空出的時段跳過；不保證能取消已進入正式發佈的任務。
- 以影片內容防止重複加入排程，不因改檔名而視為新影片；再次發佈需要使用者明確指定。初次啟用比對既有已發佈資料夾，但不將其視為平台發佈證據。
- 需要使用者介入的失敗、授權失效與發佈結果不明透過 Email 通知；成功紀錄留在排程清單。收件地址與寄信服務待配置。
- 成功發佈後雲端影片保留 7 天再刪除，本機已發佈影片保留；雲端保留發佈紀錄。未成功或待核對的影片不套用成功後刪除規則，另訂處置與取消清理策略。
- 優先以免費方案小量驗證；任何付費部署先列明費用與限制供使用者決定，不保證長期免費。
- Q16 調整：由定時任務掃描待發佈資料夾，發現新影片時建立候選排程，讓使用者填寫文案並審核；不採每批手動下令才掃描。候選排程尚未獲核准，不能直接啟用發佈。
- Q17：已上傳且啟用的排程以雲端紀錄為準，本機刪檔、改名或移動不會自動取消；需要明確取消並取得成功結果。
- Q18：定時掃描改為每兩天一次，不採每小時掃描；實際掃描時間與首次掃描日期於啟用時設定。Mac 關機或休眠時無法完成本機掃描，錯過的掃描於恢復可用後補掃，不重複建立同一影片的候選排程。
- Q19：發現新影片並建立候選排程後，寄 Email 提醒使用者回到對話填文案及審核；同一支待審影片不因重複掃描而反覆通知。文案未完成或尚未核准的影片不發佈。
- Q20：審核時若建議日期已過，重新安排至下一個可用的固定發佈時段，再請使用者確認；不立即發佈，也不變動其他已核准影片的日期。

## 啟用與規劃待辦

- 使用者對整體流程的最終確認，之後才進入實作規劃。
- 實際掃描時間與首次掃描日期，啟用時提供；掃描每兩天與發佈每兩天為兩個獨立節奏，不能將掃描成功視為發佈授權。
- 配置細節：雲端供應商、憑證保存、通知收件地址與寄信服務，留待實作規劃及配置時確定。
- 實際首發日期，首次啟用時提供，不阻擋目前的流程討論。

## 流程摘要

每兩天掃描本機待發佈資料夾 → 內容比對防重複 → 建立候選排程並 Email 通知 → 使用者在對話中填寫文案、調整順序並確認時間 → 上傳影片並啟用雲端排程 → 本機歸入已排程 → 雲端於固定隔日 20:00 正式發佈 → 本機下次連線同步正式發佈結果並移入已發佈。

本摘要的上傳與本機移動先後，實作時必須以可恢復狀態處理；上傳失敗不得誤標為可發佈，移動本機檔案失敗也不得讓同一影片重複入列。

## 事實與核實限制

- 本機實際成片目錄為 `~/Desktop/Reels 成片/`（有空格）；待發佈有 3 支 MP4，已發佈有 53 支影片，已排程目錄尚不存在。檔案位於已發佈不等於已驗證 IG 發佈結果。
- 掃描本機資料夾需要 Mac 開機且任務能讀取該目錄；Mac 離線時，雲端只能處理已傳送並核准的影片，無法發現尚在本機的新影片。
- 已安裝的匯出技能使用有空格路徑，但 repo 內技能與 README 仍是無空格版本；整合時須對齊，這次只記錄差異，尚未修改技能。
- Meta 官方 Postman 列出 Reels 建立媒體 container、等待處理完成、正式發佈的不同步驟，支援帶入 caption。
- URL 上傳方式需要 Meta 可讀取影片，本機資料夾路徑不是影片 URL。
- Instagram Login 的官方集合列出商業與創作者帳號，以及 basic/content_publish 權限。
- 目前採外部服務保存排程、到點呼叫發佈流程的設計；尚未完整核實所有原生排程欄位。
- Container 效期、目前登入配置、帳號權限與審查條件須在實作前重新核實；不保證自用一定免審。
