## T01 — 授權指定 IG 帳號並完成單支核准影片發佈

### Parent

規格 #1。

### What to build

使用者完成官方授權、核對帳號後，透過工具明確核准一支影片與文案，完成影片傳輸、媒體處理及正式發佈，取得可核對結果。此票驗證真實平台能力，不設定持續排程。

### Acceptance criteria

- [ ] 重新核實目前官方登入、權限、媒體規格與處理效期，並回報此帳號是否具備所需能力；未配置或不符時清楚阻擋，不假定自用免審。
- [ ] 操作入口能核對授權帳號，安全保存憑證；憑證不出現在 repo、聊天或一般日誌。
- [ ] 只對使用者明確核准的具體影片與文案執行測試發佈，等待媒體就緒後才正式發佈，並保存平台識別碼與可取得連結。
- [ ] 失敗或回應不明時不宣稱成功，不自動再次正式發佈；未取得真實發佈授權時只做模擬測試並明確標記真實驗證尚未完成。
- [ ] 共同操作入口的模擬整合測試通過，並附真實帳號及影片驗證結果或具體外部阻擋原因。

### Blocked by

None，可立即開始。

### Spec coverage

User Stories 1、22、23；官方 API 可行性、憑證與真實發文授權限制。

## T02 — 成片進入候選清單並防止重複入列

### Parent

規格 #1。

### What to build

使用者將成片放進指定來源後，可透過工具掃描並查看持久保存的候選清單；改名、重跑或既有已發佈影片不會無意間重複入列。這張票提供單次掃描，定時執行由 T06 補上。

### Acceptance criteria

- [ ] 對齊既有匯出技能與實際成片來源，只掃描指定資料夾；不移動或發佈未核准影片。
- [ ] 排除複製中、不可讀取及不適用檔案，顯示可理解原因；空資料夾正常完成。
- [ ] 以內容辨識重複，候選資料可在重啟後保留；改名或重複掃描不另建同一候選。
- [ ] 可初始比對既有已發佈影片，但標示為本機歸檔依據，不捏造平台成功紀錄；使用者明確指定重發才允許再入列。
- [ ] 從指定來源到候選清單的公開入口驗證檔案穩定性、空輸入、重複、改名、重啟及明確重發。

### Blocked by

None，可與 T01 獨立開始。

### Spec coverage

User Stories 4、5、6、7、34；匯出交接位置修正。

## T03 — 在對話中填文案、調整順序並確認固定發佈時段

### Parent

規格 #1。

### What to build

使用者透過對話可呼叫的操作入口查看候選影片、輸入文案、調整順序、指定首發日期並確認批次，得到明確綁定影片與內容版本的核准清單。此票不以核准本身宣稱雲端已啟用。

### Acceptance criteria

- [ ] 清單包含影片、文案、順序、日期及 Asia/Taipei 時區，可修改及整批確認。
- [ ] 從指定首發日的 20:00 起按固定隔日節奏安排；新批次接在最後一筆有效安排後，不侵入既有時段，空缺不改變節奏。
- [ ] 文案不完整、影片不可用或未核准時不得形成可啟用清單；核准綁定內容與時間，變更會使受影響核准失效。
- [ ] 候選日期過期時提出下一可用時段並要求再確認，不立即發佈、不挪動既有安排。
- [ ] 透過共同入口及可控制時間驗證上述行為，包括重啟後核准保存；清楚區別核准、傳送中與已啟用狀態。

### Blocked by

T02。

### Spec coverage

User Stories 10–19、30；固定時段及核准邊界。

## T04 — 核准影片上傳後由雲端準時發佈

### Parent

規格 #1。

### What to build

使用者啟用一筆已核准安排後，工具傳送影片及核准內容至雲端，雲端在指定時段使用官方 API 發佈。Mac 掃描端停止仍可執行；初始交付可安全停止故障項目，不具備 T07 的自動補發能力。

### Acceptance criteria

- [ ] 提供可驗證單筆雲端排程的服務選型與限制說明，優先免費方案；若需付費，先取得具體費用確認才部署。
- [ ] 上傳與啟用可查進度並恢復，缺少核准、內容版本不符或上傳未完成時不能啟用；重新送出不建立重複發佈工作。
- [ ] 雲端保存影片、核准安排及平台結果；20:00 為目標發佈時間，提前準備媒體並核對就緒條件，不捏造平台零延遲保證。
- [ ] 持久任務在服務重啟及重複觸發後不盲目重送正式發佈；不明結果先停為待核對，不以資料夾名稱或上傳成功代替平台成功。
- [ ] 完成模擬整合驗證及 Mac 掃描端停止時的雲端排程驗證；真實發佈使用另外核准的影片、文案與時間，結果可查。

### Blocked by

T01、T03。

### Spec coverage

User Stories 16、20–23、30；排程持久化、部署與失敗先安全停止。

## T05 — 取消或修改已啟用排程並查看真實結果

### Parent

規格 #1。

### What to build

使用者透過對話工具明確取消或修改既有排程，看到雲端確認結果；取消不挪動其他影片，修改內容或時間需重新核准，不能在新舊版本之間誤發。

### Acceptance criteria

- [ ] 未進入正式發佈的項目可明確取消；操作回報確認成功、失敗或待核對，不把請求送出當成取消成功。
- [ ] 核准後修改影片、文案或順序會使受影響安排重新待審；舊版本不繼續發佈，新版本未核准不啟用。
- [ ] 已進入正式發佈的競爭情境回報真實狀態，不承諾一定可取消，不自動刪除已公開貼文。
- [ ] 取消保留原日期空位；本機刪除、改名及移動不會取消雲端安排，排程清單可反映雲端結果。
- [ ] 透過共同入口驗證取消競爭、重複取消、修改後未核准與其他任務日期不變。

### Blocked by

T04。

### Spec coverage

User Stories 19、31、32、33。

## T06 — 每兩天自動發現成片並寄出待審提醒

### Parent

規格 #1。

### What to build

配置首次掃描日、時間與收件地址後，本機定時掃描產生候選清單，透過 Email 引導使用者回到對話填文案與審核。Mac 不可用時不承諾掃描成功，恢復後補掃。

### Acceptance criteria

- [ ] 每兩天自動執行，掃描與發佈日期各自獨立；休眠、關機、無權限與恢復的行為可查，錯過後只補必要掃描，不產生通知風暴。
- [ ] 發現新的待審候選即寄出審核提醒，通知可引導辨識候選批次；使用者可透過已完成的對話操作補文案與確認。
- [ ] 同一候選重複掃描不重複提醒；沒有新候選時保持安靜，寄信失敗可查且不使候選消失。
- [ ] 配置寄信服務及收件地址，隱藏憑證；需要付費先取得費用確認，不因未核准候選而啟用發佈。
- [ ] 驗證自動掃描、補掃及通知去重，並向使用者指定的收件地址做已授權的通知驗證。

### Blocked by

T03。T03 已包含對 T02 的依賴，不重複列出。

### Spec coverage

User Stories 2、3、8、9；Email 配置及待審提醒。

## T07 — 發佈故障安全補發、核對結果並通知

### Parent

規格 #1。

### What to build

對已啟用的任務提供可理解的恢復流程：可安全確認未發佈的暫時錯誤補發至當晚 20:30；已成功但回應遺失或無法確定結果時核對，必要時暫停並寄 Email，不重複發片。

### Acceptance criteria

- [ ] 能區分媒體尚未就緒、明確失敗、授權失效及正式發佈結果不明，保留可供核對的識別與進度。
- [ ] 只有可確認不重複的情況才補發；到當晚 20:30 停止新補發嘗試，後續影片日期不變。
- [ ] 模擬平台已成功但回應遺失及程序中斷，先核對或標記待核對；不以「本機沒收到成功」直接重新發片。
- [ ] 需要介入的失敗、授權失效及不明結果寄 Email；寄信失敗不改寫發佈結果，恢復後可查真實結果及核對紀錄。
- [ ] 透過共同入口與可控制時間驗證重啟、重複觸發、20:30 邊界及成功回應遺失，不以真實重複發片測試故障。

### Blocked by

T04、T06。T06 提供已驗證的 Email 配置與通知能力。

### Spec coverage

User Stories 26–29；不明結果的安全核對與失敗通知。

## T08 — 雲端結果同步回本機並正確歸檔

### Parent

規格 #1。

### What to build

已啟用影片歸入已排程；正式發佈成功後，本機同步雲端結果並移入已發佈。Mac 離線期間雲端繼續執行，本機恢復後補同步，檔案移動失敗不導致重發。

### Acceptance criteria

- [ ] 只有雲端確認啟用後才歸入已排程；正式成功且有平台結果後才歸入已發佈，失敗或不明項目不誤歸檔。
- [ ] Mac 離線時保留真實雲端結果，恢復後可重複安全同步；已成功歸檔不因重跑而覆寫既有成片。
- [ ] 改名、移動、缺檔或同名檔衝突時清楚回報本機同步問題，不改寫平台成功、不重新發片或取消雲端任務。
- [ ] 剪輯技能交付位置、候選掃描及結果歸檔使用相同的使用者配置；不移動未經本流程核准的影片。
- [ ] 驗證關機後雲端成功、本機恢復同步、移動失敗與重啟重跑，區分平台成功及本機待整理狀態。

### Blocked by

T04。

### Spec coverage

User Stories 21、24、25、33；三階段資料夾與雲端權威結果。

## T09 — 成功七天後清理雲端影片並保留紀錄

### Parent

規格 #1。

### What to build

成功影片到保留期限後自動刪除雲端影片副本，使用者仍能查看發佈紀錄及本機成片。未成功、待核對或仍被有效任務使用的資料不因清理而消失。

### Acceptance criteria

- [ ] 從已核實成功時間計算七天，未到期不刪除；清理可重複執行並顯示失敗或待清理結果。
- [ ] 清理僅作用於本流程的雲端媒體副本，不刪本機影片、平台貼文或持久發佈結果。
- [ ] 尚未成功、結果不明或仍供其他有效重發任務使用的媒體不能被成功清理規則刪除。
- [ ] 取消及停用的暫存清理、帳號解除連接及憑證撤銷有明確操作說明，不將它們混同於成功保留期限。
- [ ] 使用可控制時間驗證期限邊界與不同任務狀態，透過真實儲存整合確認刪除範圍受控。

### Blocked by

T04。

### Spec coverage

User Stories 35、36；雲端副本清理及停用操作。

## T10 — 封裝個人 plugin 並完成整體啟用驗證

### Parent

規格 #1。

### What to build

把已驗證的發佈操作與工作流程技能接入可安裝的個人 plugin，使用者可以在對話中完成候選查看、文案確認、啟用、修改、取消與查結果，並具備可重現的安裝、啟用及停用說明。

### Acceptance criteria

- [ ] 封裝相關技能及所需工具連接，安裝後可操作完整流程；不另建文案網站或要求一直開啟對話。
- [ ] 配置帳號、來源、收件地址、首次掃描時間與首發日，核對服務免費限制與執行成本；付費變更維持先確認。
- [ ] 整體示範覆蓋新影片、Email、對話審核、雲端定時、Mac 離線及恢復歸檔，並展示取消與失敗處理；真實發片依具體授權執行。
- [ ] 安裝不自動發佈既有影片，未配置時清楚顯示缺項；暫停掃描與暫停雲端發佈有明確區別，停用結果可核對。
- [ ] 整合與部署驗證結果、限制及操作說明完整，GitHub repo 不包含影片或憑證；不以模擬結果宣稱真實部署通過。

### Blocked by

T05、T07、T08、T09。T07 已依賴 T06，因此不重複列 T06。

### Spec coverage

User Stories 37、38；部署、使用與整體流程驗證。

## Coverage and readiness

38 項 User Stories 均有對應任務；各任務均由共同公開操作入口驗證外部行為。T01 與 T02 可立即開始；T03 完成後 T06 不必等雲端發佈，T04 完成後 T05、T08、T09 可獨立推進，T07 同時需要雲端發佈與 Email。

尚未取得 Meta 授權、服務配置或指定真實測試發文的核准。這些會是對應任務的外部依賴，而不是捏造已完成；具體供應商選型及官方 API 現況在相關任務啟動時核實。
