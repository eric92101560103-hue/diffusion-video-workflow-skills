# IG Reels 高品質出片

## 啟動條件

使用者確認目前版本人工審核完成並要求匯出時執行，例如「審核好了，幫我出片」。本次直接要求使用此技能匯出，視為已通過人工審核與匯出授權，不重複詢問。只要求建立、檢查技能或僅說字幕完成，不代表要立即出片。

沿用已核准的畫面、字幕、剪接與音量。技術檢查不代替人工審核；發現需改內容、位置或構圖的問題時，指出問題再處理。

## 1. 確認輸出目標

先讀安裝版本的 `/Applications/Diffusion Studio.app/Contents/Resources/docs/skills/editor.md` 與 `reference/tools/export.md`，以本機文件確認 API。用 `context` 取得目前專案，讀取其入口 JSX 與 `package.json`，取得實際場景 ID、尺寸、時長及 workarea，禁止沿用前一專案識別碼。

匯出目前人工審核的場景；有多個場景且目標不明時，只問要哪個。預設目標為整片；若 workarea 只包含局部且未授權片段輸出，先確認範圍，保留原設定。畫面須為 9:16；其他比例先確認構圖，不自動裁掉已核准內容。

## 2. 套用高品質上傳設定

只合併更新 `package.json` 中該場景的 `diffusion.export.<實際sceneId>`，保留其他專案設定與其他場景。這是使用者的 Reels 上傳版預設，不是平台唯一格式或最高畫質保證；當次明確指定的參數優先。

```json
{
  "format": "mp4",
  "video": { "enabled": true, "codec": "avc", "bitrate": 20000000, "fps": 30, "resolution": 1080 },
  "audio": { "enabled": true, "codec": "aac", "sampleRate": 48000, "bitrate": 256000 }
}
```

9:16 場景會輸出為 1080 × 1920；`resolution` 指短邊。已核准專案明確使用 60 fps 時保留 60 fps，其他情況預設 30 fps；不補幀。保持專案原始畫布解析度，靠匯出縮放，不改場景或字幕座標。若輸入本身低於目標尺寸，先告知放大不會增加原生細節。

## 3. 驗證與匯出

執行 `check`；資產載入失敗、非預期黑畫面、字幕異常需先釐清。用 `capture` 抽查開頭、中段、結尾及最長字幕，確認載入完成與實際構圖；既有人工核准樣式維持原樣。

用 Diffusion `export` 匯出到專案內 `exports/` 的唯一暫存 MP4 路徑，不直接把未完成檔案寫入待發佈資料夾。匯出回傳的設定與尺寸須符合預期。所有檢查與編碼使用本機工具，不呼叫付費轉錄、影音理解或生成工具，不消耗 Diffusion AI credits。

完成後以 `probe` 或 `ffprobe` 確認 MP4、H.264、1080 × 1920（明確覆寫時依指定）、fps、AAC、音軌及時長；時長誤差不超過一個輸出影格或可解釋的音訊封包差異。以本機 FFmpeg 對完整成片做解碼檢查，例如 `ffmpeg -v error -i <成片> -f null -`，並抽看成片前、中、後幀，確認字幕已燒錄。若專案原本有聲音，確認成片並非意外全靜音。必要時核對與專案音軌一致，不擅自調音。

檢查失敗時保留診斷，修正明確技術原因後再輸出；不把失敗檔交付或盲目降低畫質反覆重試。

## 4. 交付到桌面

預設目的地為 `~/Desktop/Reels 成片/待發佈/`。先檢查既有相近名稱資料夾，沿用使用者已有的成片目錄，避免另建僅空格不同的副本；確定不存在時才建立，並按當前執行環境的檔案權限操作。

檔名使用 `<影片名稱>_IGReels_<台北時間YYYYMMDD-HHMMSS>.mp4`。名稱優先用使用者指定，其次用有意義的專案名稱；Untitled／未命名專案改用主要素材名稱。清理路徑分隔符。同名時加版本序號，以不覆寫方式建立新檔，保留既有成片。

將驗證通過的成片複製到目的地，核對大小與 SHA-256；交付失敗時保留專案內成片，明確回報位置與原因，不宣稱桌面交付成功。保留來源素材與專案，不自動上傳、排程或發佈 IG。

完成回覆只列可點選的成片完整路徑、尺寸／fps、時長與驗證結果。只有實際輸出並核對目的地檔案後才能宣稱出片完成。
